# Building for a device

`apps/native` is the shell as a React Native app with the Rust kernel linked
in. Its native projects, `apps/native/ios/` and `apps/native/android/`, are
generated by `expo prebuild` from `app.json`, the config plugins under
`apps/native/plugin/` and the module under `apps/native/modules/platform/`,
and are not kept: a fresh checkout or worktree has neither until it is
prebuilt.

There is no task that builds the kernel ahead of the app. Each platform's
build runs `apps/native/script/build-native.ts` itself — the pod's "Build the
kernel" phase on iOS, a Gradle task per variant on Android — for the
configuration and system being built: Debug with the kernel's `dev` settings,
Release without, as a deployed page is. cargo is a no-op when the Rust has not
changed. Both find cargo and Deno at `~/.cargo/bin` and `~/.deno/bin`.

A **Release** build embeds the JavaScript bundle and runs without Metro. A
**Debug** build loads it from Metro (`deno task dev:native`) on port 8081, and
only one Metro can hold the port — check that the running one serves the tree
you mean before trusting what a Debug build shows.

## iOS

### Once per machine

- Xcode with a signing team for a phone, CocoaPods, Node (for Expo's native
  build), and the Rust targets, which `rust-toolchain.toml` installs.
- Node on `PATH` for `prebuild` and `pod install`, and named for Xcode's
  script phases in `apps/native/ios/.xcode.env.local`
  (`export NODE_BINARY=…`), which prebuild does not write.

### Generate

```bash
(cd apps/native && deno install && deno run -A npm:expo@57.0.25 prebuild --platform ios --no-install)
(cd apps/native/ios && pod install)
```

Again after anything under `modules/platform/` gains a file (a new Swift
file is added to the pod only by `pod install`), after `app.json` or a plugin
changes, or after a dependency is added.

### Build, install, launch

From `apps/native/ios`. The phone's xcodebuild id and its devicectl id differ;
`xcrun devicectl list devices` gives the second, `xcrun xctrace list devices`
the first.

```bash
xcodebuild -workspace pixelet.xcworkspace -scheme pixelet -configuration Release \
  -destination 'id=<xcodebuild id>' -derivedDataPath build/derived \
  DEVELOPMENT_TEAM=<team> CODE_SIGN_STYLE=Automatic -allowProvisioningUpdates -quiet
xcrun devicectl device install app --device <devicectl id> build/derived/Build/Products/Release-iphoneos/pixelet.app
xcrun devicectl device process launch --terminate-existing --device <devicectl id> me.plei.pixelet
```

For the simulator: `-configuration Debug -destination 'id=<simulator id>'`
with no signing, then `xcrun simctl install booted
build/derived/Build/Products/Debug-iphonesimulator/pixelet.app` and `xcrun
simctl launch booted me.plei.pixelet`. The kernel phase builds the
simulator's target itself.

`--console` on the launch streams the app's stdout, where the kernel's last
words go (`[pxl] …`).

### What has gone wrong

- **"Unable to find a destination"**: the phone dropped off; `devicectl list
  devices` shows it `unavailable`. Reconnect or unlock it.
- **Install works, launch fails "could not be unlocked"**: the phone is
  locked. Unlock it and launch again.
- **Debug fails to link on `facebook::react::Sealable`**: React Native's
  prebuilt core was left as its Release build under a Debug app. The
  prebuilt-flavor plugin marks it as of no configuration on every `pod
  install`, so it should not recur; if it does, `printf None >
  Pods/React-Core-prebuilt/.last_build_configuration` (and the same in
  `Pods/ReactNativeDependencies/` and `Pods/`, Hermes's) and build again.

## Android

### Once per machine

- Android Studio. In its SDK Manager: **SDK Tools** — NDK (Side by side),
  CMake, Android SDK Command-line Tools; **SDK Platforms** — the platform and
  an **ARM 64 v8a** system image (the 16 KB page size one, as new phones
  are) for an emulator. Accepting the licenses is the person's to do.
- An AVD from that image (Device Manager), or a phone with USB debugging on.
- **JDK 17.** A newer one (Android Studio's own is 25) fails the NDK's native
  build of expo-modules-core with "A restricted method in java.lang.System
  has been called". `apps/native/.java-version` names 17 for jenv:
  `jenv add <JDK 17 home>` once, and Gradle run under `apps/native` gets it
  (`jenv exec ./gradlew …`, or `JAVA_HOME` set by jenv's export plugin).
- The Rust target `aarch64-linux-android`, which `rust-toolchain.toml`
  installs.

### Generate

```bash
(cd apps/native && deno install && deno run -A npm:expo@57.0.25 prebuild --platform android --no-install)
```

`plugin/android-build.js` writes what the build is for into
`gradle.properties`: arm64-v8a alone, since the kernel is built for no other
ABI and an APK carrying one without it dies on those phones, and Android 10
(API 29) and later, for Vulkan.

### Build, install, launch

From `apps/native/android`, with `ANDROID_HOME=~/Library/Android/sdk` and
the platform tools' `adb`:

```bash
jenv exec ./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell am start -S -n me.plei.pixelet/.MainActivity
```

`./gradlew :app:installRelease` builds and installs in one. The kernel's last
words and panics go to logcat under the tag `pxl`:
`adb logcat -d | grep -E "FATAL| pxl |ReactNativeJS"`.

On an emulator: grant location (`adb shell pm grant me.plei.pixelet
android.permission.ACCESS_FINE_LOCATION`), and put it where there is data —
`adb emu geo fix 126.9780 37.5665` is Seoul; its default is outside Korea,
which draws no terrain. `adb exec-out screencap -p > shot.png` for a look.

### What has gone wrong

- **`dlopen failed: cannot locate symbol …`**: the core named something only
  one system has (it was `os_unfair_lock`). What differs by system is behind
  `cfg(target_vendor = "apple")` / `cfg(target_os = "android")`, and the
  gate clippies pxl-native for both targets.
- **"This app isn't 16 KB compatible"**: a native library aligned for 4 KB
  pages. `build-native.ts` links the kernel with `-z max-page-size=16384`;
  check a build with `llvm-readelf -lW <lib>.so` (every LOAD's alignment
  `0x4000`).
- **`Surface::configure` refuses `Bgra8Unorm`**: Android's Vulkan surfaces
  offer RGBA. The device backend takes the system's preferred format
  (pxl-render `gpu/api/device.rs`), as the page takes the browser's.
