# Building for a device

`ts/app/native`'s native projects, `ts/app/native/ios/` and `ts/app/native/android/`,
are generated by `expo prebuild` and not kept: a fresh checkout has neither
until it is prebuilt. Each platform's build runs
`ts/app/native/script/build-native.py` itself to build the kernel; no task
builds it ahead.

A **Release** build embeds the JavaScript bundle and runs without Metro. A
**Debug** build loads it from Metro (`make dev-native`) on port 8081, and
only one Metro can hold the port — check that the running one serves the tree
you mean before trusting what a Debug build shows.

Before a Release, bring the build number up to date:

```bash
make sync-build-number
```

## iOS

### Once per machine

- Xcode with a signing team for a phone, CocoaPods, and the Rust targets,
  which `rust/rust-toolchain.toml` installs.
- Node, as `ts/app/native/package.json`'s `engines` asks, on `PATH` for `pod
  install`, and named for Xcode's script phases in
  `ts/app/native/ios/.xcode.env.local` (`export NODE_BINARY=…`), which prebuild
  does not write.

### Generate

```bash
(cd ts/app/native && deno install && deno run -A npm:expo@57.0.25 prebuild --platform ios --no-install)
(cd ts/app/native/ios && pod install)
```

Again after anything under `modules/platform/` gains a file (a new Swift
file is added to the pod only by `pod install`), after `app.config.ts` or a plugin
changes, or after a dependency is added.

### Build, install, launch

From `ts/app/native/ios`. The phone's xcodebuild id and its devicectl id differ;
`xcrun devicectl list devices` gives the second, `xcrun xctrace list devices`
the first.

```bash
xcodebuild -workspace pixelet.xcworkspace -scheme pixelet -configuration Release \
  -destination 'id=<xcodebuild id>' -derivedDataPath build/derived \
  DEVELOPMENT_TEAM=<team> CODE_SIGN_STYLE=Automatic -allowProvisioningUpdates -quiet
xcrun devicectl device install app --device <devicectl id> build/derived/Build/Products/Release-iphoneos/pixelet.app
xcrun devicectl device process launch --terminate-existing --device <devicectl id> me.plei.pixelet
```

For the simulator: `-configuration Debug -destination 'id=<simulator id>'`
with no signing, then `xcrun simctl install booted
build/derived/Build/Products/Debug-iphonesimulator/pixelet.app` and `xcrun
simctl launch booted me.plei.pixelet`.

`--console` on the launch streams the app's stdout, where the kernel's last
words go (`[pxl] …`).

### An Apple Vision Pro

The iPhone app runs on visionOS as it is, in a window. In the simulator,
once Xcode has the runtime (`xcodebuild -downloadPlatform visionOS`):

```bash
xcodebuild -workspace pixelet.xcworkspace -scheme pixelet -configuration Release \
  -destination 'id=<Vision Pro simulator id>' -derivedDataPath build/derived
xcrun simctl install <id> build/derived/Build/Products/Release-iphonesimulator/pixelet.app
xcrun simctl location <id> set 37.2741,127.0437
xcrun simctl launch <id> me.plei.pixelet
```

### What goes wrong

- **"Unable to find a destination"**: the phone dropped off; `devicectl list
  devices` shows it `unavailable`. Reconnect or unlock it.
- **Install works, launch fails "could not be unlocked"**: the phone is
  locked. Unlock it and launch again.

## Android

### Once per machine

- Android Studio. In its SDK Manager: **SDK Tools** — NDK (Side by side),
  CMake, Android SDK Command-line Tools; **SDK Platforms** — the platform and
  an **ARM 64 v8a** system image (the 16 KB page size one) for an emulator.
  Accepting the licenses is the person's to do.
- An AVD from that image (Device Manager), or a phone with USB debugging on.
- **JDK 17.** A newer one (Android Studio's own is 25) fails the NDK's native
  build of expo-modules-core with "A restricted method in java.lang.System
  has been called". `ts/app/native/.java-version` names 17 for jenv:
  `jenv add <JDK 17 home>` once, and run Gradle as `jenv exec ./gradlew …`.
  Opening the project in Android Studio rewrites Gradle's daemon criteria
  (`android/gradle/gradle-daemon-jvm.properties`) for its own Java 25, which
  outranks `JAVA_HOME`; prebuild again to restore them.
- The Rust target `aarch64-linux-android`, which `rust/rust-toolchain.toml`
  installs.

### Generate

```bash
(cd ts/app/native && deno install && deno run -A npm:expo@57.0.25 prebuild --platform android --no-install)
```

The app has two flavors, `mobile` for a phone and `quest` for a Meta Quest,
so every variant is named for both: `mobileRelease`, `questDebug`. A phone
takes only `mobile`. `plugin/android-build.ts` names both flavors' debug
variants to React Native as debug builds.

### Build, install, launch

From `ts/app/native/android`, with `ANDROID_HOME=~/Library/Android/sdk` and
the platform tools' `adb`:

```bash
jenv exec ./gradlew :app:assembleMobileRelease
adb install -r app/build/outputs/apk/mobile/release/app-mobile-release.apk
adb shell am start -S -n me.plei.pixelet/.MainActivity
```

`./gradlew :app:installMobileRelease` builds and installs in one; a bare
`installRelease` is ambiguous between the flavors and fails. The kernel's last
words and panics go to logcat under the tag `pxl`:
`adb logcat -d | grep -E "FATAL| pxl |ReactNativeJS"`.

On an emulator: grant location (`adb shell pm grant me.plei.pixelet
android.permission.ACCESS_FINE_LOCATION`), and put it where there is data —
`adb emu geo fix 126.9780 37.5665`; its default is outside the data, which
draws no terrain. `adb exec-out screencap -p > shot.png` for a look.

### A Meta Quest

The `quest` flavor: `assembleQuestRelease`, or `assembleQuestDebug` for one
that asks Metro, and `adb` as for a phone. A headset takes `adb` once its
developer mode is on (the Meta Horizon phone app, under a Meta developer
account) and it is plugged in and trusted.

Without one, Meta's Spatial Simulator is an Android emulator for 2D panel
apps. `npx metavr@latest init` signs in to a Meta account, and also installs
Meta's agent skills into the home directory; it leaves no `metavr` on
`PATH`, so it runs through npx:

```bash
npx metavr tools install spatialsim
npx metavr ssim start    # an emulator adb sees, emulator-5554 if it is the first
adb install -r app/build/outputs/apk/quest/release/app-quest-release.apk
adb shell cmd location set-location-enabled true
adb emu geo fix 127.0437 37.2741
```

Its location is off until turned on, and it has no network provider, so the
position is only what `geo fix` gives.
